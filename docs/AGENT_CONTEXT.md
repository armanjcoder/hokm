# Hokm Club — Context Handoff

> این فایل برای ادامه‌دادن کار در یک session جدید است. کل محتوای فایل را کپی کن
> و به‌عنوان اولین پیام به agent جدید بده. هیچ توضیح اضافه‌ای لازم نیست.

## ۱) قواعد همکاری (سخت‌گیرانه رعایت شود)

**زبان**
- کاربر فارسی می‌نویسد. توضیح‌ها، گزارش‌ها و نقدها **به فارسی**.
- کد، کامنت‌های داخل کد، نام متغیرها و پیام‌های commit **به انگلیسی**.
- تمام متن‌هایی که کاربر نهایی می‌بیند **فارسی**؛ فقط کدهای ماشین‌خوان خطا
  (مثل `ROOM_NOT_FOUND`) انگلیسی می‌مانند.

**روش کار — مهم‌ترین قاعده**
1. هر فاز را به زیرمرحله‌های کوچک بشکن.
2. **در هر نوبت فقط یک زیرمرحله** را پیاده کن.
3. اجرا کن: `npm run build` · `npm run test` · `npm run typecheck`.
4. بعد **در نقش یک منتقد بسیار سخت‌گیر** خودت را از ۰ تا ۱۰ نقد کن، در همه‌ی
   ابعاد فنی **و بصری**.
5. نمره باید **واقعی** باشد. چون خودت کد را نوشته‌ای یا چون نسبت به قبل بهتر
   شده، نمره را بالا نبر. جمله‌ی خود کاربر:
   > «ممکنه یک بخش رو بهبود داده باشی ولی هنوزم میتونسته خیلی خیلی بهتر بوده باشه»
6. **هر بُعدی که زیر ۹.۵ شد، همان را اصلاح/بازطراحی کن و دوباره نقد کن.**
   این حلقه را تا بالای ۹.۵ تکرار کن.
7. تازه بعد از آن گزارش بده و منتظر تأیید کاربر بمان.

**این فایل را همیشه به‌روز نگه دار**
- بعد از هر مرحله‌ای که تمام می‌شود، همین فایل را خودت به‌روز کن: موارد جدید را
  اضافه کن، چیزهای تغییرکرده را اصلاح کن و مطالب منسوخ را حذف کن.
- کاربر نباید یادآوری کند؛ این بخشی از تعریف «تمام شدن» یک مرحله است.

**اثبات کن، فرض نکن**
- ادعاها باید با اندازه‌گیری یا regression probe ثابت شوند: عمداً باگ تزریق کن،
  ببین تست قرمز می‌شود، بعد برگردان.
- اگر چیزی را نتوانستی واقعاً اثبات کنی، **صریح بگو نتوانستی**. اثبات جعلی ممنوع.
  (سابقه: یک بار هارنس jsdom ساخته شد که `type="module"` را اجرا نمی‌کرد و
  نتیجه‌اش بی‌اعتبار بود؛ همان‌جا صادقانه اعلام شد.)
- **درس گران‌قیمت (چهار بار تکرار شد):** «کد هست» با «کد کار می‌کند» یکی نیست.
  وجود یک کلاس CSS یا یک keyframe در فایل، هیچ اثباتی نیست. اگر چیزی ظاهراً درست
  است ولی کاربر می‌گوید کار نمی‌کند، **سیستم را در حال اجرا اندازه بگیر**، نه
  اینکه دوباره کد را بخوانی. برای انیمیشن یعنی: تأیید کن `element.animate()`
  واقعاً صدا زده می‌شود؛ برای زمان‌بندی یعنی: سرور واقعی را اجرا کن و
  timestampها را چاپ کن.
- **probe باید در سطح درستی باشد.** اگر probe صفر خطا داد، یعنی **تست تو ناقص
  است**، نه اینکه کد سالم است. آن حفره را ببند و دوباره probe بزن. (سابقه:
  تست‌ها فقط `PlayingCard` را مستقیم می‌سنجیدند، پس قطع‌شدن اتصال آن با
  `TableSeat` را نمی‌گرفتند — و باگ دو بار زنده ماند.)

**امنیت**
- هرگز secret را commit نکن. `.env` در gitignore بماند.
- کاربر توکن ربات را چند بار در چت paste کرده. بارها به او گفته شده در BotFather
  `/revoke` بزند — **هنوز تأیید نکرده که انجام داده**. در فرصت مناسب یادآوری کن.

**گیت**
- فقط روی `arena/019fb173-hokm` کار کن و فقط به همان push کن.
- **خطر محیطی مکرر:** workspace چند بار وسط کار re-clone شده و تاریخچه‌ی محلی
  یتیم شده (یک بار کار commit‌نشده هم پرید). الگوی بازیابی:
  `git stash -u` → `git fetch origin <branch>` → `git reset --hard FETCH_HEAD`
  → `git stash pop` → **حتماً بررسی کن فایل‌ها سر جایشان هستند** → rebuild.
  نشانه‌اش: `tsc: not found` یا ناپدیدشدن `node_modules`.

## ۲) تصمیم‌های محصولی که کاربر گرفته (تکرار نکن، نقض نکن)

| موضوع | تصمیم |
|---|---|
| فاز ۳.۲.۴ (امتیاز کوت قابل تنظیم) | **رد شد** — «اصلا خوب نیست» |
| فاز ۳.۲.۵ (لاگ رخدادهای بازی) | **رد شد** — «قشنگی بازی حکم به اینه که آدم حواسش باشه چه کارت‌هایی تا حالا بازی شده و طبق اون استراتژی بچینه» |
| آیکن میزبان | **تاج (👑) ممنوع** — با «حاکم» اشتباه می‌شود |
| قوانین اختیاری (ده‌لو کم / بام) | پیش‌فرض **روشن** — «چون تو بازی واقعی هم همینجوریه معمولا» |
| هدف طراحی UI | مدرن، مینیمال، جوان‌پسند، جذاب، RTL فارسی، موبایل‌محور برای تلگرام |
| تم | **همیشه تیره** با پالت بنفش تیره؛ هرگز از تم روشن تلگرام پیروی نکن |
| تعیین حاکم | با کشیدن کارت تا آمدن آس، **روی خود صندلی‌ها** دور میز؛ اگر دور اول کسی آس نیاورد، کارت جدید **روی کارت قبلی** انباشته شود |
| پخش کارت | دانه‌دانه و نوبتی، از حاکم شروع؛ حتماً **قابل مشاهده** و نه سریع |
| خروج از میز | آیکن کوچک در **گوشه‌ی بالا**، نه دکمه‌ی بزرگ پایین صفحه |
| ریتم ربات‌ها | باید فاصله‌ی محسوس داشته باشند؛ نباید آنی بازی کنند |
| هویت بازیکن | آواتار حروف اول، **مشترک بین لابی و میز** تا همان فرد در هر دو جا شناخته شود |
| رنگ تیم | همیشه **نسبت به بیننده** (سمت خودت بنفش، حریف کهربایی) و هرگز فقط رنگ — همیشه برچسب متنی هم باشد |
| فیلد آدرس بک‌اند | داخل تلگرام **پنهان** شود؛ فقط در مرورگر ساده لازم است |

## ۳) وضعیت فعلی پروژه

**تست‌ها: ۸۳۹ تست، همه سبز** — game-engine ۱۲۲ · api ۲۳۲ · web ۴۸۵
`npm run build` ✅ · `npm run typecheck` ✅

**فازهای تمام‌شده**

- **فاز ۱** — MVP: monorepo، موتور بازی، Express+Socket.IO+grammY، مینی‌اپ React/Vite.
- **فاز ۲.۱** — پایداری SQLite با `sql.js`.
- **فاز ۲.۲** — پیام‌های خطای فارسی؛ `.npmrc`؛ `playerToken` مخفی با
  `timingSafeEqual`؛ reconnect خودکار Socket.IO؛ UX «ادامه‌ی میز».
- **فاز ۲.۳** — اعتبارسنجی HMAC روی `initData`، انقضای ۲۴ ساعته، پس‌گرفتن صندلی.
- **فاز ۲.۴** — چرخه‌ی عمر میز: میزبان، ready-up، ربات‌ها، ترک میز، `abandoned`.
- **فاز ۲.۵** — rate limiter، پاک‌سازی نام، نوشتن اتمی DB، خاموشی تمیز.
- **فاز ۲.۶** — ماژولارسازی کامل (`server.ts` از ۸۶۸ به ۷۷ خط).
- **فاز ۳.۱** — سه حالت بازی با `ModeConfig`؛ فازهای `discarding`/`drawing`.
- **فاز ۳.۲.۱–۳.۲.۳** — امتیاز هدف، ده‌لو کم، بام.
- **فاز ۳.۲.۶** — سه سطح ربات، قابل تغییر در لابی، ترکیب‌پذیر.
- **ممیزی کامل** — ۳۰ بررسی امنیتی، هارنس ۷۲۰ مسابقه‌ای، ۲۷ تست جدید UI.
- **فاز ۴.۱** — سیستم طراحی: فونت Vazirmatn **محلی** (باگ CDN فیلترشده)،
  `tokens.css` با ~۹۰ توکن، `safe-area`، `dvh`، `viewport-fit=cover`.
- **فاز ۴.۲** — میز واقعی: چیدمان بازیکنان دور میز، کارت جلوی صاحبش،

- **فاز ۴.۳** — کارت‌ها و انیمیشن: طراحی استاندارد کارت (index در گوشه)،

- **فاز ۴.۴** — انتخاب حکم به‌صورت **bottom sheet** با تله‌ی فوکوس مشترک.
- **فاز ۴.۵** — ادغام با تلگرام: haptic، رنگ هدر، `viewportStableHeight`،
  جلوگیری از بسته‌شدن با swipe. همه feature-detect شده و کاملاً اختیاری.
- **فاز ۴.۶** — بازطراحی لابی و صفحه‌ی ورود: آواتار مشترک، نمایش صریح تیم‌ها در

**قرعه‌کشی حاکم (اضافه‌شده در فاز ۴.۳)**
حاکم قبلاً **همیشه صندلی ۰** بود. حالا با کشیدن کارت تا آمدن آس تعیین می‌شود:
`drawForHakem` در موتور، فاز `choosing_hakem`، و رویداد `game:hakem_draw_done`.

## ۵.۵) بودجه‌ی زمانی انیمیشن (شکننده — با هم تغییر کنند)

این اعداد به هم وابسته‌اند. **مکث سرور باید از کل چرخه‌ی کلاینت بیشتر باشد**،
وگرنه دست بعدی شروع می‌شود و کارت‌ها قبل از جمع‌آوری عوض می‌شوند — که سه بار
باعث شد انیمیشن خروج اصلاً دیده نشود.

| مقدار | جا | پیش‌فرض |
|---|---|---|
| `TRICK_PAUSE_MS` | `apps/api/src/game/bots.ts` | ۵۰۰۰ms |
| `BOT_MOVE_DELAY_MS` | همان فایل | ۹۰۰ms |
| `LANDING_ALLOWANCE_MS` | `useTrickHold.ts` | ۹۰۰ms |
| `TRICK_HOLD_MS` | `useTrickHold.ts` | ۳۲۰۰ms |
| `TRICK_SWEEP_MS` | `useTrickHold.ts` | ۶۲۰ms |

چرخه‌ی کلاینت = ۹۰۰ + ۳۲۰۰ + ۶۲۰ = **۴۷۲۰ms** < **۵۰۰۰ms** مکث سرور ✅

هر دو با env قابل تنظیم‌اند (`HOKM_TRICK_PAUSE_MS`, `HOKM_BOT_MOVE_DELAY_MS`) و
در تست‌ها روی صفر ست می‌شوند (`server-harness.ts`). **تأخیر صفر یعنی اجرای
همزمان**، وگرنه هر حرکت یک macrotask جدا می‌سازد و تست‌ها timeout می‌دهند.

سایر زمان‌ها: پرواز کارت ۹۰۰ms، پخش هر کارت ۳۰۰ms، فاصله‌ی صندلی‌ها ۴۰۰ms،
هر کارت قرعه‌کشی ۶۲۰ms، مکث روی آس برنده ۱۵۰۰ms.

## ۵.۷) ادغام با تلگرام (`apps/web/src/telegram.ts`)

دو قانون که هرگز نباید شکسته شوند:

۱. **هیچ‌چیز نباید خطا بدهد.** برنامه در مرورگر ساده هم اجرا می‌شود و کلاینت‌های
   واقعی تلگرام اغلب چند نسخه عقب‌ترند. هر قابلیت باید feature-detect شود.
۲. **هیچ‌کدام حیاتی نیست.** نبود haptic یا رنگ هدر نباید روی بازی اثر بگذارد.

- `supportsVersion()` نسخه را **عددی** مقایسه می‌کند، نه رشته‌ای — وگرنه ۷.۹
  جدیدتر از ۷.۱۰ حساب می‌شود.
- رنگ هدر فقط از Bot API **۶.۹** به بعد (قبلش hex قبول نمی‌کند)،
  `disableVerticalSwipes` از **۷.۷**.
- haptic با `prefers-reduced-motion` خاموش می‌شود.
- رویدادهای haptic: `play` (بازی کارت) · `select` (انتخاب) · `win` (بردن دست) ·
  `error` (حرکت رد شده) · `finish` (پایان دست/بازی). عمداً کم — بازخورد روی هر
  لمس تبدیل به نویز می‌شود.
- `--tg-viewport` توسط `trackViewportHeight()` منتشر می‌شود و توکن
  `--app-height` آن را ترجیح می‌دهد (چون `dvh` داخل WebView تلگرام قابل اعتماد
  نیست). خارج از تلگرام به `100dvh` برمی‌گردد.

## ۶) ربات‌ها (اندازه‌گیری‌شده روی بیش از ۱۰۰۰ مسابقه‌ی seed‌دار با جابه‌جایی صندلی)

- **easy** — منطق درست ولی ۲۵٪ اشتباه تصادفی (`EASY_MISTAKE_RATE = 0.25`)
- **medium** — هیچ‌وقت اشتباه نمی‌کند، ارزان‌ترین برد را می‌گیرد، هرگز روی یار خودش
  نمی‌زند، بلندترین خال کناری را لید می‌کند
- **hard** — شمارش کارت، نقد کردن برنده‌های قطعی، کشیدن حکم از `DRAW_TRUMPS_FROM = 5`،
  خالی‌کردن خال، پرهیز از لید به خالی که می‌داند حریف ندارد

نتایج: medium مقابل easy **۷۴٪** · hard مقابل easy **۷۷٪** · hard مقابل medium **۵۵.۵٪**
هر سطح نسخه‌ی قبلی خودش را هم برد: easy ۹۹٪ · medium ۵۱٪ · hard ۵۲٪

⚠️ **یافته‌ی منفی مهم:** نسخه‌ای از hard که برای ذخیره‌ی حکم، برش ارزان را رد می‌کرد
از medium **ضعیف‌تر** بود (۲۷ از ۱۰۰). حذف شد — **دوباره اضافه نکن.**
برتری hard بر medium زیر حدود ۲۰۰ جفت مسابقه نویزی است (۴۷–۵۵٪)؛ تست از ۴۰۰ جفت استفاده می‌کند.

## ۷) باگ‌های بحرانی که پیدا و رفع شده‌اند (مراقب برگشتشان باش)

1. **نشت دست بازیکنان** — `toPublicView` کل `...state` را spread می‌کرد و دست همه را
   برای همه می‌فرستاد (بازی کاملاً قابل تقلب). با destructure کردن
   `hands`/`players`/`stock` رفع شد.
2. **هنگ سه‌نفره** — ۱۷ دست می‌تواند ۶-۶-۵ تقسیم شود و کسی به ۷ نرسد. رفع: وقتی
   همه‌ی دست‌ها بازی شد، به بیشترین دست داده می‌شود.
3. **راهنمای قوانین غیرقابل‌دسترس** پیش از ورود به میز. با `rulesOverlay` مشترک رفع شد.
4. **جعل `telegramId`** — کلاینت می‌توانست صندلی بدزدد. فقط `initData` تأییدشده.
5. **کرش ربات تلگرام** — rejection مدیریت‌نشده‌ی `setMyCommands` کل API را می‌کشت.
6. **readiness دوباره ارزیابی نمی‌شد** وقتی ربات آخرین صندلی را پر می‌کرد.
7. **ربات‌ها یار خودشان را می‌بردند** — در medium/hard رفع شد.
8. **temporal dead zone روی `requireConnection`** در App.tsx.
9. نوشتن غیراتمی DB و حلقه‌ی کرش با DB خراب.
10. **temporal dead zone روی `PROXY_SCHEMES`** در `config.ts` — `const` پایین فایل
    ولی مصرف بالای فایل. تست `config-init.test.ts` با `vi.resetModules()` نگهبانش است.
11. **صفحه‌ی سفید مینی‌اپ** — اسکریپت مسدودکننده‌ی `telegram.org` قبل از باندل
    `type="module"`؛ روی شبکه‌ی فیلترشده معلق می‌ماند و برنامه هرگز اجرا نمی‌شد.
12. **فونت فارسی هرگز لود نمی‌شد** — از `fonts.googleapis.com` می‌آمد که فیلتر
    است. حالا محلی است. **هیچ فونت یا اسکریپتی از CDN نگیر.**
13. **کارت‌ها عرض صفر می‌گرفتند** — اندازه فقط از `flex-basis` می‌آمد که خارج از
    یک flex container بی‌اثر است، پس کارت‌های روی میز نامرئی شدند. کارت باید
    `width`/`height` صریح داشته باشد.
14. **انیمیشن CSS هرگز اجرا نمی‌شد** — انیمیشن mount وقتی React نود را دوباره
    استفاده کند دوباره پخش نمی‌شود. همه‌ی انیمیشن کارت‌ها با
    `element.animate()` است. **به CSS animation برای کارت‌ها برنگرد.**
15. **`fill: 'both'` جلوی انیمیشن خروج را می‌گرفت** — انیمیشن پرشده برای همیشه
    مالک `transform` می‌ماند و بالاتر از CSS می‌ایستد. ورود `backwards` است و
    خروج هم با همان API اجرا می‌شود، نه CSS transition.
16. **تکان‌خوردن کل صفحه** — جایگاه کارت `min-size` داشت، پس هر کارت جدید
    صندلی را بزرگ می‌کرد و کل grid را جابه‌جا. حالا اندازه ثابت است و کارت‌ها
    در یک لایه‌ی `position: absolute` جدا هستند.
17. **وسط‌چینی با transform** — انیمیشن روی همان خاصیت می‌نوشت و کارت
    جابه‌جا می‌شد. وسط‌چینی با `inset: 0` + `place-items: center`.
18. **گلیچ یک‌فریمی** — نگه‌داشتن دست در `useEffect` تصمیم گرفته می‌شد، پس یک
    فریم بدون کارت نقاشی می‌شد. حالا **حین رندر** تصمیم گرفته می‌شود.
19. **سرور از انیمیشن جلو می‌زد** — ربات بعدی ۹۰۰ms بعد بازی می‌کرد و دست
    نگه‌داشته‌شده را پاک می‌کرد. مکث بین دست‌ها روی **سرور** است، نه کلاینت.

## ۱۰) وضعیت دامنه و شبکه

**دامنه `arman-jafari.ir`** — NS با موفقیت به Cloudflare منتقل شد
(`eleanor.ns.cloudflare.com`). قبلاً روی ArvanCloud بود؛ **آروان دیگر بی‌ربط است.**

**رکورد DNS** — `hokm` از نوع CNAME به
`a909fe96-ed01-4cf5-84ec-eec3048c641c.cfargotunnel.com` با Proxy روشن. ✅ درست است.

**تونل Cloudflare** — ابتدا شکست خورد چون ISP پورت ۷۸۴۴ را بسته بود. با
`protocol: http2` حل شد (QUIC/UDP هنوز بسته است ولی TCP کار می‌کند).
تونل با موفقیت وصل می‌شود: `Registered tunnel connection ... protocol=http2`.
`tunnelID = a909fe96-ed01-4cf5-84ec-eec3048c641c`

فایل `C:\Users\arman\.cloudflared\config.yml`:
```yaml
tunnel: a909fe96-ed01-4cf5-84ec-eec3048c641c
credentials-file: C:\Users\arman\.cloudflared\a909fe96-ed01-4cf5-84ec-eec3048c641c.json
protocol: http2
ingress:
  - hostname: hokm.arman-jafari.ir
    service: http://localhost:4000
  - service: http_status:404
```

**تضاد VPN** — با VPN سیستمی تونل قطع می‌شود؛ بدون VPN تلگرام فیلتر است.
حل شد با `TELEGRAM_PROXY_URL` که فقط ترافیک Bot API را پروکسی می‌کند.
کاربر باید کلاینت VPN را باز نگه دارد ولی حالت TUN/System-Proxy/Global را **خاموش** کند.

**اجرا:** دو ترمینال — یکی `npm run start -w @hokm/api`، یکی `cloudflared tunnel run hokm`.

## ۱۱) کارهای حل‌نشده

- **باطل‌کردن توکن ربات** — کاربر هنوز تأیید نکرده `/revoke` را زده. توکن چند بار
  در چت لو رفته است.
- **دامنه** — تونل Cloudflare با `protocol: http2` کار می‌کند، ولی هنوز موقتی
  است (لپ‌تاپ باید روشن بماند). راه دائمی VPS است.
- **hard مقابل medium فقط ~۵۵٪** — بهتر شدنش نیاز به جست‌وجوی درختی دارد؛
  به‌عنوان محدودیت پذیرفته شده.
- **جمع‌آوری کارت‌ها دقیق نیست** — کارت‌ها ۱۹۰ پیکسل به سمت برنده می‌روند و محو
  می‌شوند، نه اینکه دقیقاً روی آواتار او بنشینند. برای آن باید موقعیت واقعی دو
  المان را در زمان اجرا اندازه گرفت (تکنیک FLIP).
- **پوشش تست ناهموار در UI** — `TableScreen.tsx` و `App.tsx` هنوز پوشش پایینی
  دارند (مرحله‌ی ۴.۷ به آن می‌پردازد).
- **محدودیت محیط agent** — مرورگر واقعی در دسترس نیست، پس **اسکرین‌شات و قضاوت
  چشمی ممکن نیست**. jsdom انیمیشن و چیدمان را محاسبه نمی‌کند. هر ادعای بصری
  باید با ساختار/اندازه‌گیری اثبات شود یا صادقانه به کاربر واگذار شود.
