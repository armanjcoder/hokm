# برنامه اجرایی فاز ۲ — پایدارسازی فنی

فاز ۲ به چند بخش کوچک تقسیم می‌شود. هر بخش جداگانه پیاده‌سازی، تست، نقد و امتیازدهی می‌شود.

## ۲.۱ — لایه ذخیره‌سازی محلی

### هدف

اضافه کردن یک persistence layer برای ذخیره و بازیابی room/game state.

### محدوده این مرحله

- اضافه کردن storage abstraction
- ذخیره snapshot میزها
- load کردن میزها هنگام start بک‌اند
- persist کردن تغییرات مهم room/game
- اضافه کردن تست ذخیره/بازیابی

### خارج از محدوده این مرحله

- Telegram auth واقعی
- session امن
- UI کامل reconnect
- migration پیچیده دیتابیس
- room cleanup هوشمند

> وضعیت: **۲.۱ انجام شد** ✅

## ۲.۲ — Session و Reconnect ✅

- **۲.۲.۱** فارسی‌سازی خطاها، `.npmrc`، پیام‌های بهتر Mini App
- **۲.۲.۲** توکن نشست سری با مقایسه زمان‌ثابت (`timingSafeEqual`)
- **۲.۲.۳** reconnect خودکار Socket.IO، ردیابی disconnect، نمایش وضعیت اتصال
- **۲.۲.۴** UX بازگشت به میز قبلی با حالت‌های recovery
- **۲.۲.۵** تست خودکار restart/reconnect + پوشش typecheck برای پوشه test

## ۲.۳ — Telegram Auth ✅

- تأیید امضای `initData` با HMAC و Bot Token
- بستن حفره جعل `telegramId`
- رد کردن `auth_date` کهنه (ضد replay)
- بازپس‌گیری صندلی برای کاربر تأییدشده
- زنده ماندن API حتی وقتی تلگرام در دسترس نیست

## ۲.۴ — Room Lifecycle ✅

- host واقعی با انتقال خودکار
- دکمه «آماده بازی» با پشتیبانی از بازی ۱ تا ۴ نفره
- افزودن/حذف ربات به‌صورت تکی
- خروج از میز و وضعیت `abandoned`
- پاک‌سازی خودکار میزهای قدیمی

## ۲.۵ — تست نهایی و hardening ✅

- rate limiting درون‌حافظه‌ای روی مسیرهای نوشتن
- پاک‌سازی نام نمایشی (کاراکترهای کنترلی و bidi)
- خاموش شدن تمیز روی `SIGINT`/`SIGTERM`
- نوشتن اتمیک دیتابیس + بازیابی از فایل خراب
- تست بازی کامل تا پایان، تست همزمانی، تست ورودی بدشکل
