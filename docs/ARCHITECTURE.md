# معماری پروژه Hokm Club

هدف پروژه ساخت یک تجربه‌ی کامل حکم ایرانی در تلگرام است: ربات تلگرام برای ورود/دعوت/ساخت میز و یک Telegram Mini App مدرن برای بازی Real-time.

## تقسیم‌بندی فازها

### فاز ۱ — هسته و اسکلت قابل اجرا
- موتور قوانین حکم به صورت TypeScript خالص و قابل تست.
- API و WebSocket برای اتاق‌ها، لابی، انتخاب حکم و بازی کارت.
- مینی‌اپ React با UI مینیمال، موبایل‌محور و RTL.
- ربات تلگرام با دستورات `/start` و `/newgame`.

### فاز ۲ — محصول قابل بازی عمومی
- اتصال پایدار دیتابیس به جای حافظه‌ی موقت.
- احراز هویت امن Telegram Mini App با اعتبارسنجی `initData`.
- مدیریت reconnect، ترک میز، کیک، spectator و timeout نوبت.
- لاگ رخدادهای بازی و replay/debug.

### فاز ۳ — تجربه‌ی جذاب‌تر
- انیمیشن پخش کارت و جمع کردن دست.
- صدا و haptic feedback تلگرام.
- پروفایل، آمار برد/باخت، رنکینگ دوستانه.
- قوانین اختیاری: ده‌لو کم، بام، امتیاز هدف قابل انتخاب، ربات جایگزین بازیکن.

## ساختار Monorepo

```text
apps/
  api/                 Express + Socket.IO + Telegram Bot
  web/                 Telegram Mini App با React/Vite
packages/
  game-engine/         موتور قوانین حکم، مستقل از UI و شبکه
docs/
  ARCHITECTURE.md      این سند
```

## مسئولیت هر بخش

### `@hokm/game-engine`
هسته‌ی بازی هیچ وابستگی به تلگرام، دیتابیس یا UI ندارد. این پکیج مسئول موارد زیر است:
- ساخت دسته کارت ۵۲تایی.
- پخش اولیه ۵ کارت و تکمیل دست‌ها بعد از انتخاب حکم.
- انتخاب حکم فقط توسط حاکم.
- اعتبارسنجی حرکت‌ها و رعایت خال زمینه.
- تعیین برنده‌ی هر trick.
- امتیازدهی راند: عادی، کوت و حاکم‌کوت.
- مدیریت تغییر حاکم در راند بعد.

### `@hokm/api`
بک‌اند فعلی In-memory است و برای فاز اول مناسب است. مسئولیت‌ها:
- ساخت و مدیریت Room/Lobby.
- شروع بازی وقتی ۴ نفر حاضر شدند.
- Socket.IO events برای انتخاب حکم و بازی کارت.
- ارسال view اختصاصی هر بازیکن؛ هر بازیکن فقط دست خودش را می‌بیند.
- ربات تلگرام برای باز کردن مینی‌اپ و ساخت میز.

### `@hokm/web`
مینی‌اپ موبایل‌محور و RTL:
- صفحه ورود و ساخت/پیوستن به میز.
- لابی با نمایش صندلی‌ها و تیم‌ها.
- میز بازی، نمایش امتیاز، حکم، نوبت، کارت‌های بازی‌شده و دست بازیکن.
- انتخاب حکم با UI سریع و جذاب.

## رویدادهای WebSocket

Client -> Server:
- `room:join` با `{ roomId, playerId }`
- `game:choose_trump` با `{ roomId, playerId, suit }`
- `game:play_card` با `{ roomId, playerId, cardId }`
- `game:next_hand` با `{ roomId }`

Server -> Client:
- `room:update` شامل snapshot اختصاصی همان بازیکن.

## نکته‌های امنیتی فاز بعد

در نسخه‌ی اولیه، playerId در localStorage نگهداری می‌شود و API فقط برای توسعه است. قبل از انتشار عمومی باید:
- `Telegram.WebApp.initData` سمت سرور اعتبارسنجی شود.
- هر playerId به Telegram user id و session امضا شده وصل شود.
- Room و Game در دیتابیس ذخیره شوند تا با ری‌استارت از بین نروند.
- Rate limit و محدودیت اسپم برای ساخت میز اضافه شود.
